# Plan 083 — Codex P1: capability overclaim under a declared uncertainty note

## Finding (PR #153, chatgpt-codex-connector, P1)

The article `2026-08-26-por-que-tu-sensor-de-glucosa-...` shipped with:

- `uncertainty_note`: *"Aunque GlucoFM aprende representaciones útiles, aún no
  ha sido validado en estudios clínicos que demuestren su capacidad para
  predecir diabetes o resistencia a la insulina."*
- `requires_uncertainty_note: true`, `confidence: "Moderada — ..."`
- but `why_it_matters[1]`: *"...GlucoFM **permite una detección temprana y un
  manejo personalizado de la glucosa**, lo que podría disminuir
  complicaciones..."*

The reader-facing narrative asserts, in the present indicative, exactly the
clinical capability the post disclaims two fields away.

## Root cause

`resolve_uncertainty_counterweight` (plan 067/070) guarantees the *note* is
present and visible, but nothing reconciles the rest of the frontmatter with
it. `why_it_matters` and `headlines_variants.benefit` are sell-the-finding
fields generated by Stage 6 with no cross-check against the post's own
declared uncertainty.

## Design — a detector, not a rewriter (backend-only, fail-open)

Deterministically rewriting Spanish clinical prose was considered and
rejected: "permite" → "podría permitir" mangles compound sentences
("el modelo permite detectar la diabetes e identifica la resistencia" →
"... e podría identificar ..."), and this pipeline publishes through PRs a
human merges — generating prose no one reviewed is the wrong posture (cf.
`hero_alt.py`, which likewise declines to synthesize descriptions). So the
pass **flags and logs**; it never edits the text.

`news_collector/editorial/uncertainty.py` gains:

- `_CAPABILITY_VERBS`: closed set of present-indicative capability verbs
  (`permite`, `detecta`, `predice`, `identifica`, `diagnostica`, `anticipa`,
  `posibilita`, `habilita`, sing/plural).
- `_CLINICAL_CONTEXT_RE`: the sentence must be about a clinical/health outcome
  (`diabet`, `glucos`, `insulin`, `diagn[óo]stic`, `riesgo`, `salud`,
  `c[ée]lula`, ...) — a bare architectural claim ("permite reutilizar
  representaciones") is ignored.
- `_PRE_HEDGE_RE`: an existing hedge within ~4 words before the verb
  (`podría`, `puede`, `ayuda a`, `busca`, ...) means the claim is not a bare
  present-tense assertion — skip.
- `find_capability_overclaims(text) -> list[str]`: the sentences of `text`
  that carry an un-hedged present-indicative clinical-capability verb. `[]`
  for non-strings and clean text.
- `find_unvalidated_capability_claims(fields, *, requires_uncertainty_note,
  uncertainty_note) -> list[str]`: runs only when a counterweight is in force;
  scans `why_it_matters` (list) and `headlines_variants.benefit` (str);
  returns `"<field>: <sentence>"` strings. Never mutates `fields`.

Hooked in `ai_editor.py` frontmatter assembly, right after
`resolve_uncertainty_counterweight`. On a non-empty result it emits one
`logger.warning` ("reframe as prospective before merge: ...") for the PR
reviewer and the Codex re-review to act on. Publication is never blocked.

## Non-goals

- Editing the text / blocking publication.
- `summary_points` (they report the study's measured results) and the
  article body (judged by the fidelity critic).
- Fixing the PR #153 instance in code — delivered as a content commit on the
  PR branch (reframed `why_it_matters[1]` as prospective).
